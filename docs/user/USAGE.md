# Usage

## Files and projects in the terminal

- **The palette:** `Ctrl+Shift+P` (`Cmd+Shift+P` on macOS) drops a search list down from the top of the window; nothing is dimmed, and a click anywhere outside it, or Esc, closes it without reaching the terminal. Type to search, in this order: **Tabs** (open tabs, and the panes of split tabs by name or folder), **Commands**, **Projects** (folders your shells visited; Enter opens a new tab there) and **Files** (the focused pane's folder, searched once you pause typing; Enter opens the file in the editor beside it). With nothing typed it lists recent tabs, every command by category and your most recent projects. Arrows choose, Enter runs. **Open file…** (`Ctrl+Shift+O`, `Cmd+P` on macOS) and **Jump to project…** open it showing only Files or Projects; remove that chip with its × or Backspace to search everything.
- **Browse files:** `Ctrl+Shift+E` on Windows (`Cmd+Shift+E` on macOS), or “Browse files in terminal pane” in the command palette. The tree replaces only the focused pane's terminal view; it is not an editor or sidebar. Folder and file icons, branch guides, and single-click disclosure arrows show the expanded hierarchy; selection and hover highlight the item rather than the entire pane width. Double-clicking a folder row also expands it. `/` or `Ctrl+F` searches paths below the current folder. Arrow keys select, Enter expands a folder or copies a file path, `C` copies the selected path outside search (use `Ctrl+C` while searching), and Esc returns to the terminal.
- **Change the same shell's directory:** At an interactive Bash/Zsh prompt, run `compi tree`. Select a folder and use **Enter folder** or `Ctrl+Enter`; the shell itself performs `cd`. Esc cancels. The keyboard shortcut opens browsing and copying without changing the shell: a running program or partially typed command must never receive an injected `cd`.
- **Jump to visited directories:** Run `compi z` (or `compi jump`) from the prompt, type to filter, choose with arrows, and press Enter. This integration does not install a bare `z` command; `z orangebox` is not a Compi command. Only this shell-origin picker changes the shell's directory; **Jump to project…** in the palette opens a chosen folder in a new tab instead. Project history follows OSC 7 cwd reports, including ordinary `cd` in supported interactive shells.
- New tabs and splits inherit the focused pane's reported cwd. Tabs use the configurable metadata caption described below; manually named tabs retain their label, and split tabs show a pane-count badge. Full metadata is available through `compi --json pane list/show`, not a diagnostic hover card. Right-click any tab to open its menu at the pointer without switching to it; its tab commands (rename, split, arrange, hide, close, …) switch to that tab before running. Below them, the **Panes** group lists the tab's panes in layout order with their folder, a **· Floating** mark and program status. Click a row to switch to that tab and focus the pane; hover a row (or move to it with the arrow keys) for its **×**, which closes that pane in one click while the menu stays open (the last pane closes the tab), and its **›**, which opens the pane actions. Keys: ↑↓ move, Enter focuses, Delete closes the highlighted pane, → opens its actions, ← or Escape goes back. Mouse dragging highlights terminal text; `Ctrl+C` copies a selection instead of interrupting the shell. `Ctrl++` increases font size on Windows; `Ctrl+Enter` is distinct from Enter when a terminal program enables Kitty keyboard disambiguation.
- **Float a pane:** Right-click a pane, or click its grip **⋯**, and pick **Float pane** (the palette has it too). The same running shell moves into a movable, resizable frame above the window and stays visible while you switch tabs or workspaces; its siblings fill the space it left, and the server's split layout is unchanged. Drag the title to move it and the right/bottom edges or corner to resize; the terminal is resized to fit. **Dock pane** (in the floating title's **⋯** menu, its right-click menu, or the palette) returns it to wherever its tab now places it without restarting anything. Docking never closes or ends work: closing a pane or tab is the separate **Close pane**/**Close terminal tab** action, and ending stays the explicit **End process…** action, which always asks first and keeps the final screen. Only one pane receives typing; a floating pane that has it has an accent border. To dock by dragging, drag the title onto a pane of the float's tab: release on an edge to place it beside that pane, or on the centre **Swap** box to take that pane's place (it takes the float's tile). Released anywhere else the float just moves; Esc puts it back. Click a pane or use **Switch focus between floating and tiled panes** / **Focus next floating pane** to move it. Floats are per window and are restored on relaunch.
- **Right-click and pane controls:** right-click opens a small menu for what you clicked, never the command palette. A terminal: **Copy** (with a selection), **Paste**, **Split right/down**, then the pane actions. A floating pane's title, a content pane, and a pane's grip **⋯** (shown at the top of a pane while the pointer is over it; drag the grip to move the pane) open the pane actions alone. Every pane menu lists the same pane actions in the same order: **Focus** (when the pane is not focused), **Move to new tab** (needs another pane in the tab), **Float pane**/**Dock pane**, **End process…** (terminals; asks first, the pane stays with its final screen) and **Close pane**. Empty header space: **New tab**, **New workspace**, **Split right/down**, **Toggle sidebar**. A Files row: **Open**, **Open diff** (when changed), **Copy path**, **Copy relative path**; a Changes row: **Open diff**, **Open file**, **Stage**/**Unstage**, **Discard changes…**; both end with a **Pane** submenu. The editor keeps its own menu. A floating pane's title also shows **⋯** and **×** on hover; its **×** closes the pane with the same confirmation rules as **Close pane**.
- **Settings:** `Ctrl+,` (`Cmd+,` on macOS) opens Settings as a pane beside the focused one, or focuses the window's Settings pane if it is already open. With no tab open it gets a tab of its own; the empty window also has a **Settings** button. Its header holds the section icons (Appearance, Interface, Terminal, Keyboard, Performance, Updates, Advanced; hover for the name, the current one underlined) and a search icon: click it, press `Ctrl+F`, or just type to search every section, and each group of results is labelled with its section and group, such as **Interface · Tab metadata**; Esc on an empty search folds it back. Settings sit in cards, labelled by group in sections that have several; choices such as pane density and the focus indicator are shown as small drawings, and themes are tiles you preview before applying, grouped as **Yours** (the current theme and favourites), **Dark** and **Light** ([configuration](CONFIGURATION.md)). The pane splits, floats, docks, moves and closes like any pane, and stays open across restarts.
- **Monitor:** **Monitor** in the palette (or the **Monitor** button in an empty window) shows the machine Compi's server runs on, as a pane beside the focused one; if the window already has one, it is focused. The rail on the left lists **Overview**, **Processes**, **CPU**, **Memory**, **Disk** and **Network** with live values (just icons when the pane is narrow; hover for the name). **Overview** shows a card for each with its history as columns of dots; click a card (or arrow to it and press Enter) for its page, Esc goes back. **Memory by type** splits memory the way the system does: App, Wired, Compressed, Cached and Free on macOS, Used, Cached and Free elsewhere. The header picks the range the graphs cover (**1m**, **5m**, **15m**, **1h**) and pauses them; history is kept for the last hour even while no Monitor is open. On **Processes**, type in the search field (`Ctrl+F`, `Cmd+F` on macOS) to match a process's name, command line, path, user or PID; **All / Apps / My processes / System** narrow the list (Apps is hidden where the system can't tell apps apart). Click a column heading to sort by it, again to reverse; CPU is a share of the whole machine. While the pointer is over the table the rows stay in place and only their values change, so a row doesn't jump away as you reach for it; moving off re-sorts. A dash means a value isn't available: macOS doesn't let Compi read some details of other users' processes. Processes are sampled every 2 seconds, only while the Processes page is on screen.
- **Arrange panes and tabs:** Run **Arrange panes and tabs** from the palette, or **Arrange** from a tab's right-click menu. Under **Tabs to combine**, click (or press Enter on) any other tab in this workspace to fold its panes into the current tab; click it again to leave that tab out. Built-in arrangements are Columns, Rows, Grid, Main + stack (side), Main + stack (top), and Equalize, which keeps the existing splits and evens their sizes; saved presets appear below them. Clicking or arrowing to a layout only previews it: the preview shows each pane's numbered place, across every combined tab, before anything moves. Double-click, Enter, or **Apply** commits it; **Cancel**, Esc, or clicking outside leaves everything as it was. **M** mirrors left/right and **F** flips top/bottom. Arranging only moves and resizes existing panes: no shell restarts and no pane is replaced. Combined tabs become one tab and disappear from the tab strip. Main + stack puts the focused pane in the large slot. A preset with fewer slots than panes stacks the extra panes in its last slot; a preset with more slots drops the unused ones. **Mirror/Flip pane arrangement** work directly on the current tab, **Swap pane left/right/up/down** exchanges the focused pane with its neighbor, and **Restore previous pane arrangement** undoes the last change: it restores the earlier layout, or, right after combining, splits the tabs back out (restoring a layout again swaps back). **Split merged tabs back out** recreates the combined tabs at any later time, with their names, order, and splits; panes you detached or removed since stay where they are. **Save pane arrangement as preset** stores the tab's split shape, never its terminals, in `[layout_presets.NAME]` of `config.toml` (up to 32 presets, 2–16 panes each; reusing a name replaces it); select a saved preset and press Delete twice to remove it. Floating panes keep floating and dock into their assigned slot. Swap commands have no default shortcuts; bind them under `[keybindings]`, for example `swap_pane_left = "ctrl-alt-left"`.
- **Move a pane:** Hover a pane to reveal the **⋯** grip in the middle of its top edge. Click it for the pane menu, or drag it to move the pane. Over another pane of the same tab, release on an edge to place the pane beside it, sharing that pane's space evenly, or on the centre **Swap** box to exchange the two; only the zone under the pointer is highlighted, the half the pane will take or the Swap box, over a faint preview of where the pane will land. Release on another tab to add the pane to it on the right; rest on a tab for a moment to switch to it while dragging, then drop beside one of its panes. Release on empty tab-bar space to give the pane its own tab. Esc, or releasing anywhere else, cancels. The shell keeps running: nothing restarts, and **Restore previous pane arrangement** undoes a move within a tab.
- **Edit files:** A content pane (opened with `compi files` or `compi edit`, see below, or from the palette, see the next item) shows its folder until you open a file: click a file, or select it with the arrow keys and press Enter. Type to filter the folder to matching names (Backspace edits the filter, Esc clears it); only folders you have expanded are searched. Hover the filter field for the keys. Open files appear as tabs above the editor; click a tab to switch, × to close it (a dot marks unsaved changes). Hover a tab for the file's full path and where it lives (host, `WSL: Ubuntu`, or `SSH: host`); the right end of the tab row names the same place. The folder button at the left of the tabs shows or hides the folder beside the file. The editor highlights syntax (files over 512 KB open as plain text, so typing stays quick), numbers lines and searches with `Ctrl+F` (`Cmd+F`); `Ctrl+S` (`Cmd+S`) saves, keeping the file's line endings. Files over 1 MiB and files that are not text show their size, path and a **Copy path** button instead of the editor. A read-only file opens read-only, marked *Read-only* on its tab; saving it offers **Save as…** instead. Compi never overwrites changes made outside it without asking: while a file is on screen, Compi checks it every couple of seconds. If it changed and you have no unsaved edits, the new text loads in place and the cursor stays where it was. If you have unsaved edits, a *changed on disk* note offers **Reload** (discard your edits) or **Keep mine**. If you save over a newer file anyway, the note offers **Reload**, **Overwrite** (replace what is on disk with your text) and **Save as…** (type another path; the tab switches to the new file and the original is left alone). A file deleted outside Compi keeps its text, and saving creates it again. Reload asks for a second click when it would discard edits. Closing never loses edits silently: closing a file tab, a pane, a tab or a workspace with unsaved files, moving such a tab to another window, closing the window, quitting, restarting the daemon or installing an update first lists the files and offers **Save** (`Enter`; if any file cannot be saved, nothing closes and its tab says why), **Don't save** and **Cancel** (`Esc`). Unsaved text is also kept on disk within a second of typing, so after a crash, an update restart or a reopened window the file comes back with your edits and a note *Restored unsaved edits from …* (plus the *changed on disk* note if the file changed meanwhile). Edits of files no longer open are offered by **Recover unsaved edits…** in the command palette, which opens the file beside the focused pane; kept edits are deleted after 30 days. Compi shortcuts (palette, splits, pane focus, sidebar, …) keep working while you type, Esc leaves the editor (or closes Save as) for the pane, and Enter or a click returns to it. Open files stay open across restarts.
- **Open files from a terminal:** In the command palette, **Files** shows the focused terminal's current directory in a content pane beside it, reusing one in the tab that already shows that folder; in a content pane it shows the pane's own folder (beside an open file, as the folder sidebar) and gives it the keyboard. **New editor** always opens a new content pane beside the focused pane. **Open file…** (`Ctrl+Shift+O`, `Cmd+P` on macOS) opens the palette on the focused pane's folder; type part of a file's path and Enter or a click opens it beside the pane, and nothing is typed into the terminal. Typing a file name in the full palette finds it too. Open file… searches WSL and Unix folders; for a native Windows folder use Files. All three need the terminal's directory: the one its shell last reported (OSC 7, see below), else the one it started in.
- **Open a file printed in a terminal:** `Ctrl`-click (`Cmd`-click on macOS) a path such as `src/main.rs`, `./web/app.ts:4`, `/etc/hosts` or `crates/x/y.rs:12:3` (also `File.cs(12,5)`) to open it beside the terminal at that line. Relative paths start from the terminal's current directory, in its own environment (WSL or host). Compi first checks that the path is a readable file; otherwise it only shows a note. Web links keep opening in the browser, and `file://` hyperlinks (OSC 8) open in the editor.
- **Review changes:** In a Git repository the folder sidebar switches between **Files** and **Changes** (palette **Changes**, or `compi diff`). Changes lists **Unstaged** and **Staged** files with their status letter and line counts, as a list or a tree. Click one to show its diff in that file's tab: each file has one tab, and its **Edit / Diff** switch (`Ctrl+Shift+D`, also **Diff this file** in the palette) flips between editing and the diff at the same line. A tab showing a diff has a small diff icon, its tooltip names what it compares, and a staged diff says `staged` in its header. A deleted file opens only as a diff. Edits you have not saved stay in the editor while you look at the diff, which compares the saved file (the header says `Unsaved edits not shown`). Diffs show side by side when the pane is wide (switch with Auto/Unified/Split), highlight the changed words, fold unchanged lines (click a fold to show more, `e` expands everything) and search with `Ctrl+F`. `n`/`p` jump between changes, and `[`/`]` step through changed files. Each diff names what it compares (`Working tree vs index`, `Index vs HEAD`). Diffs and the list follow edits made anywhere, including in the terminal.
- **See changes while editing:** Open files in a repository mark lines that differ from the index in the editor's left edge: a bar for added or changed lines, a small wedge where lines were deleted. Unsaved edits count. The tab row says `vs index` (or `untracked`). Click a mark or `vs index` to switch the tab to its diff there. **Next change** / **Previous change** (`Alt+F5` / `Alt+Shift+F5`) move between changes. The marks only show changes; they never stage anything.
- **Stage and commit:** Hover a file in Changes for **+** (stage), **−** (unstage) and **↺** (revert its uncommitted changes); the Unstaged and Staged headings stage or unstage everything. In a diff, hovering a change shows its **Stage hunk** / **Unstage hunk** button beside the first line (whitespace set to Exact); after `n`/`p`, `Shift+S` / `Shift+U` moves the current change. The header's **Stage** / **Unstage** (`s` / `u`) and **Discard changes…** act on the whole file. Reverting always asks first, lists each file, and deletes new (untracked) files; it can't be undone. Write the message in the box at the top of Changes and press `Ctrl+Enter` (`Cmd+Enter` on macOS) or **Commit**. **Amend** rewrites the last commit and loads its message. Hooks run as usual; if Git refuses, its message shows under the box.
- **Branches, fetch, pull and push:** The top of Changes shows the branch (or `detached at <commit>`) and how far it is from its upstream, such as `↑2 ↓1`; its tooltip says when it is up to date, and a branch without an upstream says `no upstream`. Click the branch (or use **Switch branch…** / **Create branch…** in the palette) to pick another one: type to filter, Enter switches, and the `Create branch “name”` row makes a branch at HEAD and switches to it. Remote branches switch to a new local branch that tracks them. Uncommitted changes come along; if they would be overwritten, Git's message shows in the picker and nothing is stashed or forced. **Fetch**, **Pull** and **Push** (buttons at the top of Changes, also in the palette) type `git fetch`, `git pull` or `git push` into a terminal beside the editor: one of that tab's terminals waiting at a prompt in the repository folder, else a new one opened there in the repository's environment, so password, SSH-key and 2FA prompts work. A branch without an upstream pushes with `git push -u origin <branch>`, and the Push tooltip says so. Nothing is ever force-pushed. The ahead and behind counts follow within a couple of seconds.

Compi installs its bundled Bash/Zsh shell integration into the shell's home directory when starting supported default shells (Windows/WSL2, macOS, and remote Unix daemons); it does not edit your startup files. Explicit custom executable/argument profiles are left untouched. A Bash login profile that replaces `PROMPT_COMMAND` may suppress cwd reports after ordinary `cd`; `compi tree` and `compi z` report the shell's current directory before opening their picker, so they start from the directory you are in even without the prompt hook.

On Windows/WSL2, Compi's default shell finds Windows commands (`pwsh.exe`, `code`, `explorer.exe`, …) through `~/.compi/wincmd.<id>`, small launchers for every command in your Windows search path, instead of WSL's `/mnt/c/...` search directories. Lookups of missing commands and command-name completion stay fast; Windows programs still see your Windows `PATH`. Compi refreshes the launchers when those Windows directories change. Directories your startup files add to `PATH` are kept as they are.

On Windows/WSL2, the tree can browse a shell directory linked into a mounted Windows drive. If the WSL share cannot follow the link, Compi resolves that directory in WSL and retries through its Windows path.

## Shell lifecycle and recovery

New tabs and splits open directly into the terminal canvas. Starting a shell shows no bar, spinner, delayed indicator, or reserved space.

Ended shells, launch failures, disconnected panes, and attachment conflicts retain their terminal canvas without recovery overlays, status buttons, or diagnostic hover cards. Final output and the last observed terminal name remain available after the shell ends. Use the existing pane-actions menu or command palette for explicit restart/attachment actions; inspect errors and exit codes through **Diagnostics** or `compi --json pane show`. Retrying attachment never takes control from another window. **Reconnect window** reconnects without restarting shells.

Shells that ended because Compi's background service restarted (for example after an update) come back on their own: the first time such a tab is on screen, it starts a fresh shell in the directory you were last in, or in its starting directory if that one no longer exists. Earlier output is gone. Shells you end yourself, or that fail to start, stay ended until you restart them.

## Shell prompt

**Settings → Terminal → Shell prompt** (or “Prompt settings” in the palette) styles the prompt your shells already draw with [Oh My Posh](https://ohmyposh.dev) or [Starship](https://starship.rs). Compi does not install either one, has no prompt of its own, and uses each style exactly as the provider defines it. It works where your shells run: the local account, the WSL2 distribution you pick, or the SSH host.

- **Details** shows where Compi is looking, your login shell, provider paths, startup-file lines that already set up a prompt, and any warning, such as an Oh My Posh installed only on Windows that cannot draw a WSL prompt. Bash and Zsh are supported. Fish, PowerShell, and custom launch profiles are not.
- **Pick a style:** every style is listed with its real prompt rendered under its name: your current configuration first, then the provider default, Oh My Posh themes, or Starship presets. Browsing changes nothing, and the prompt is independent of the terminal theme and layout.
- **Apply:** click a style and choose **Apply** in the popover under it, or **Cancel**. Compi shells use the style without any edit to your startup files; new ones start with it and running ones switch at their next prompt. **Also use outside Compi** additionally adds a marked `# >>> compi prompt >>>` block to the end of your login shell's `~/.bashrc` or `~/.zshrc`; the popover then shows that file's diff first. Nothing else in the file changes, and shells outside Compi need a new shell.
- **Back up, restore, turn off:** each change backs up the managed files to `~/.compi/prompt/backups`. **History** restores any of the last 20 backups and **Turn off** removes every prompt Compi manages, each confirmed in the same kind of popover. Your own provider configuration is copied, never edited.

## Command-line workspace control

The public `compi` CLI uses the same persistent workspace as the native client. Supported Compi shells expose the matching CLI to child processes on `PATH` and inherit instance and pane context, including the Windows application bridge from WSL. No agent-specific integration is required:

```sh
compi split --panes 4 --layout grid
compi --json pane list
compi run -- printf '%s\n' 'hello world'
compi pane capture --scope scrollback --format text
```

`--panes` is the total, not the number to add. Existing shells and IDs survive; missing panes are created. A lower total is rejected without deleting anything. Creating missing panes and arranging the final tree is one revision-checked atomic transaction: preflight or revision failure leaves no partial additions. JSON returns one mutation receipt containing every affected pane and surface ID.

Outside a Compi shell, choose an existing daemon with `--instance NAME` or `--connect USER@HOST[:PORT]`; `--instance ''` selects the default instance. Without a target, the CLI uses the only running local daemon and fails with the list of running instances when there are several, including older ones it cannot inspect. CLI commands do not start a missing daemon. Bare `compi` and `compi PATH` still open the GUI; inside a Compi shell they open the shell's instance, and a word that is neither a command nor a directory fails with a usage error suggesting the closest command (`compi fiiles` → `did you mean 'files'?`). Targets are stable `--workspace ID|NAME`, `--tab ID|WORKSPACE/NAME`, `--pane ID|SURFACE_ID`, and native `--window ID`; ambiguous names or windows fail rather than guessing. An explicit pane selects its containing tab/workspace, and explicit parent selectors replace incompatible inherited shell context.

| Command | Actions |
|---|---|
| `workspace` | `list`, `show`, `create NAME`, `rename NAME`, `close` |
| `tab` | `list`, `open [--name NAME] [--cwd PATH]`, `rename NAME`, `focus`, `move --index N [--workspace DEST]`, `detach`, `close`, `merge --with SOURCE... [--layout PRESET]`, `unmerge` |
| `pane` | `list`, `show`, `focus`, `resize [--cols N] [--rows N]`, `swap --with OTHER`, `zoom`, `unzoom`, `float`, `dock`, `close`, `terminate`, `send (--text TEXT | --key KEY)`, `capture [--scope screen|scrollback] [--format text|ansi]` |
| `window` | `list` |
| `split` | `[--right | --down] [--cwd PATH]`, or `--panes TOTAL --layout PRESET [--cwd PATH]` |
| `files` | `[DIR]` |
| `edit` | `[FILE[:LINE[:COL]]]` |
| `diff` | `[PATH[:LINE[:COL]]]` |
| `layout` | `list`, preset ID/name, `mirror`, `flip`, `restore` |
| `update` | `[--check]` |
| Other | `run -- COMMAND [ARG...]`, `attach`, `detach`, `theme install FILE.json`, `changes`, `--version` |

Built-in layouts: `columns`, `rows`, `grid`, `main-side`, `main-top`, `equalize`; named `[layout_presets]` work too. Move indices are zero-based. Resize changes pane geometry through existing dividers or a float frame, not the native window size; at least one dimension is required. GUI presentation commands require an existing native GUI host on the machine executing the CLI and an explicit or uniquely eligible window; they do not open a substitute preview or bypass an open dialog. Only explicit focus commands activate a window; tab detach opens its destination in the background.

`pane send --text` is literal, with no implicit Enter; use `--key enter` to submit. `run` safely quotes POSIX shell argv and submits Enter, but does not wait for completion; it rejects unsupported shells, alternate-screen applications, and control characters. Capture observes screen text/styles without attaching, resizing, or taking input ownership; scrollback includes retained history and screen. `attach` requires an interactive console and an unattached pane; Ctrl-] leaves it. `detach` releases only a CLI console attachment, never a GUI view. `tab detach` transfers the existing native view.

`pane list`, `pane show` and `window list` give each pane a `type`: `terminal`, or `content` for a pane that shows a folder instead of a shell. Content panes focus, swap, zoom, float, dock, move and close like terminals; closing one ends no process, so it asks only when a window holds unsaved edits in it. `window list` reports those files as the pane's `unsaved_files`. Commands that need a shell (`pane send`, `capture`, `terminate`, `resize`, `run`, `attach`, `detach` and single-pane `split`) exit 3 on a content pane, and `split --panes` refuses a tab that holds one, because it sizes panes in terminal cells.

`compi files [DIR]` browses a folder, and `compi edit FILE[:LINE]` opens a file, in a content pane beside the terminal you run them in, using that terminal's environment (the host, or its WSL distribution). Paths are relative to the shell's current directory; `compi edit` with no file, or with a folder, browses like `compi files`. A content pane already in the tab is reused: `files` focuses one showing that folder, and `edit` adds the file to one whose folder holds it. Otherwise a new pane opens to the right, rooted at the shell's directory, or at the file's folder when the file lies outside it. `edit` shows the file with the cursor on LINE (default 1); a `:COL` suffix, as compilers print it, is accepted and ignored. A missing or unreadable file is reported in the editor. When no Compi window shows the tab, the pane still opens and the one-line output ends with `not shown: …`; `--json` reports `pane_id`, `opened`, `shown`, `not_shown`, the mutation `receipt` (null when nothing changed) and the resulting `workspace`.

`compi diff FILE[:LINE]` shows the file's uncommitted change in that file's tab (opened, or switched to Diff), scrolled to LINE, in the content pane of its Git repository (reused from the tab, or opened to the right rooted at the repository's top folder). When the file has both unstaged and staged changes, the unstaged one (your edits against the index) is shown. Plain `compi diff` lists the changes of the shell directory's repository in that pane's **Changes** sidebar. Outside a repository, or for a file without changes, it says so and exits 1. Paths resolve as for `compi edit`, and a checkout on a Windows drive opened from WSL (`/mnt/c/…`) is read with Git for Windows. `compi diff` only reads Git; files and the index change only through the stage, commit and revert buttons above. In a repository the folder tree also marks changed files with their status letter (M, A or ? for new, R, ! for conflicts) and folders holding changes with a dot; hover a marked file for the **Open diff** button.

Close confirms interactively before ending live processes or discarding unsaved edits. `pane close`, `tab close` and `workspace close` ask the open Compi windows for files with unsaved edits in the content panes they would remove (with no window open there are none; if open windows cannot be asked, close fails with exit 1 and nothing closes), list each pane and file, and ask `Close and discard unsaved changes? [y/N]`; only `y` or `yes` closes. When processes would end too, one prompt names both and you type `close`. Noninteractive close returns exit 4 with code `confirmation_required`, and the `--json` error lists `unsaved_files` as `{pane_id, path}`; there is no `--yes`/`--force` bypass. Scripts must explicitly `pane terminate`, save or revert files in their window, inspect the resulting state, then close. `--json` emits `{ok,result}` or `{ok,error}`; stable IDs, lifetimes, revisions, metadata availability, and mutation receipts are available to automation. Exit codes: 0 success, 1 operation/transport failure, 2 arguments, 3 missing/ambiguous target, 4 confirmation, 5 unavailable daemon/attachment, 6 revision/generation/lifetime conflict. Run `compi COMMAND ACTION --help` for individual syntax.

Without `--json`, commands that change something print one line, for example `New pane pane-…` after a split or `2 new panes: …` after growing a tab, and `pane send` and `run` print nothing on success. `compi --version` prints the version.

`compi changes` prints the running version with its headline and the other highlights, then each section of **What's new** under its title. Like `--version`, it needs no running Compi. `--json` returns `version`, `summary`, `highlights` and `sections` (each with `title` and `notes`).

```text
Compi 0.1.7 · WSL tab completion: 41.8 s → 0.07 s
  WSL unknown command: 95 → <1 ms
  …

Speed
  WSL finds Windows commands in one local folder, not dozens of /mnt/c folders.
  …
```

### Updating from the terminal

`compi update --check` prints the running version and, when there is one, the newer release with its headline:

```text
Compi 0.1.7 · 0.1.8 available
  WSL tab completion: 41.8 s → 0.07 s
```

`compi update` downloads and verifies the same signed package as **Settings → Updates**, on one progress line. It then lists the shells a restart would end, saying so when the shell you typed in is one of them, and asks `Restart now? [y/N]`. Only `y` restarts. The running Compi window performs the restart exactly as the Updates page does: it saves the windows, ends only the listed shells and reopens into the new version, so a listed shell running the command closes with it. With no window open, Compi opens first. Without an interactive terminal, for example from a script or agent, the command stops after the download with exit 4; restart from a terminal or **Settings → Updates**. There is no bypass. `--json` reports the same results, and builds without a release verification key report that updates are unavailable.

## Tab and pane metadata

**Settings → Interface → Tab metadata** controls directory, active process, Git branch/changes, and dimensions independently. Directory is on by default; other fields are off. A manual tab label remains primary. Otherwise the focused pane (or first layout pane) supplies the caption; split tabs keep a pane-count badge and a separate dirty/stale indication. Captions truncate and retain the last meaningful value when metadata is unavailable. Full per-pane metadata is available through CLI inspection; diagnostic hover cards are removed.

Collection runs in the terminal's actual environment: native Unix, the selected WSL distribution, or the SSH daemon host. The process is the foreground job, not the Windows launcher. Git uses the reported cwd; unavailable and stale fields are explicit rather than fabricated. Refresh is cached and bounded, runs off the UI thread, and never attaches or resizes a pane. `compi --json pane list/show` exposes the same environment, process, Git, directory, dimensions, and per-field state.

## Program status

Programs that support the [Program Status Protocol](https://www.superlogical.com/rex/docs/build/program-status) (OSC 7501) report whether they are idle, working, blocked on you, done or failed. Compi answers their feature query, so programs that report only after asking work too.

- A tab shows a glyph for the state that most needs you across its panes: blocked, then error, working, done and idle. Background tabs and other workspaces are included. A tiled pane shows a dot in its top edge, and a floating pane shows the glyph and progress in its title strip. The sidebar and palette put the state first in the tab's status line. Each of the three can be turned off under **Settings → Interface → Program status** ([configuration](CONFIGURATION.md#program-status)).
- Hover a glyph or dot for each pane's name and every record it reported: program, title, state, what it waits for, progress and message.
- Work in progress ends at the next shell prompt or when the process exits; finished and failed results stay until you press a key in that pane or close it.
- `compi --json pane list/show` includes each terminal's `program_status` records.

A shell function can report status too:

```sh
status() { printf '\e]7501;state=%s:msg=%s\e\\' "$1" "$(printf '%s' "$2" | base64 | tr -d '\n')"; }
status working "Syncing photos"; rsync -a ~/Photos backup:/photos && status done "Photos synced" || status error "rsync failed"
```

## Remote connections

Compi starts its sibling server automatically, and relaunching with the same instance name reconnects to that workspace. Use `--working-directory PATH` when you intentionally want new work to start in a specific directory.

To open the native client against an SSH host:

```sh
compi --connect dev@example.com:2222
```

The headless diagnostic client accepts the same `--connect` and optional `--instance` options. For example, `compi-probe --connect dev@example.com workspace` prints the remote hierarchy and lifecycle state, while its session, tab, pane, surface, soak, and shutdown commands operate through the same protocol. `compi-probe tab arrange <tab-id> <preset> [--with <tab-id>]... [--main <pane-id>] [--mirror] [--flip]`, `tab mirror|flip|restore-arrangement|split-merged <tab-id>`, and `pane swap <pane-id> <pane-id>` rearrange existing panes in place; each `--with` merges another tab of the same workspace into `<tab-id>`. Presets are the built-in IDs (`columns`, `rows`, `grid`, `main-side`, `main-top`, `equalize`) or a `[layout_presets]` name from the local configuration. The remote host must provide `compi-daemon` on `PATH`.
