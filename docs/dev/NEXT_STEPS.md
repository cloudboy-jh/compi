3. **Task manager**, feature 4 in the features doc: a content pane with Pulse as the interaction reference, in Compi's look. One phase per session, checked in `cargo dev` on Windows and a Mac.
   - Shape: a third `PaneContent` kind, `TaskManager { target, page }` (protocol 28, workspace file format 5 with a placeholder so format-4 daemons refuse the file rather than misread it), wired everywhere `Settings` is (validation, store migration, `render_content_pane`, tab title, open/focus like `open_settings`, palette command, CLI `PaneType`, probe handoff). The daemon collects; the client renders. A `WatchSystemMetrics { target, detail }` subscription, modelled on `WatchProgramStatus`, runs collection only while a visible pane watches it and coalesces samples; expensive detail (one process's history, per-process disk/network) is requested only for the selected process. History is bounded and lives in the client while the pane is open. Unavailable, permission-denied, stale and disconnected are explicit values, never zero.
   - The target is where the daemon runs. The Mac and a Windows host collect natively. A connected host is its remote daemon, so `--connect` needs no extra transport. WSL needs a long-lived collector inside the distribution (one `wsl.exe --exec` child streaming `/proc` samples), because today's WSL calls are one-shot. Totals and PIDs are never mixed across targets.
   - Decision in 4a: the `sysinfo` crate for host processes, CPU, memory, disks and networks, or more raw platform calls in the style of `perf.rs` and `lifecycle_inventory.rs`. GPU is outside both.
   - **4a. Processes on the host.** Content kind, protocol and store format, the open command, the subscription and a host collector on its own thread. Processes page: search over name, command/path, PID and user; All / Apps / My processes / System; sortable CPU, memory, threads, CPU time, PID and user columns; stable selection and predictable order while the user interacts.
   - **4b. Inspector and quitting.** Right-hand inspector (identity, CPU/memory history, command/path, start time, state, parent/children), or a detail view with Back in narrow panes. Quit / Force quit as peer actions with confirmation, aimed at `(pid, start time)`; the daemon revalidates both before signalling and never signals a group. No such check exists today. Open terminal for Compi-owned processes (matched by surface shell pid and process lifetime).
   - **4c. Overview and resource pages.** Metric navigation with live values; Overview cards with short history graphs that open their page; CPU total/per-core and user/system, memory/available/swap/pressure, disk and network activity with volumes and interfaces.
   - **4d. Targets.** Target selector for the Windows host, each WSL distribution (the streaming collector, with PID revalidation and kill inside the distribution) and connected hosts.
   - **4e. GPU and polish.** GPU utilization, memory and engines (DXGI/PDH on Windows, IOKit on macOS, unavailable elsewhere); app-grouped rows with real icons; resizable columns with saved visibility and order.
   - Out of scope: Pulse embedding, notebooks, databases, a TODO board, battery/sensors, menu-bar monitoring, package management.

Out of scope for Git: history graphs, interactive rebase, a stash UI, force-push, line-level staging.
