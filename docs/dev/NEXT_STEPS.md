3. **Monitor** (feature 4, "Task manager" in the features doc): a resource monitor in a content pane, Pulse's structure (navigation, Overview cards, detail pages, Processes) in Compi's look. One phase per session, checked in `cargo dev` on Windows and a Mac. Battery, energy by app and temperatures stay out.
   - Shape: a third `PaneContent` kind, `Monitor` (protocol 28, workspace file format 5; a Monitor leaf is stored as a marked Settings leaf so format-3 and format-4 daemons can read the file far enough to refuse it). The daemon collects; the client renders. Unavailable, permission-denied, stale and disconnected are explicit, never zero.
   - Collection: the `sysinfo` crate plus platform calls for what it leaves out (thread counts, apps, and on macOS other users' processes through set-user-ID `/bin/ps`). System totals (CPU, memory, disk, network) are sampled all the time into a 1-hour history at 2 s, so every range is filled when the pane opens. The process list is sampled only while a connection watches (`WatchSystemMetrics`), with each process's details sent once per connection.
   - The target is where the daemon runs: the Mac, a Windows host or a connected host (its remote daemon). WSL needs a long-lived collector inside the distribution. Totals and PIDs are never mixed across targets.
   - Navigation: Overview, Processes, CPU, Memory, GPU, Disk, Network with live values; icons only when the pane is narrow.
   - Done, **4a. Processes on the host.** Content kind, protocol 28 and store format 5, palette **Monitor**, the subscription and the host collector; Processes page with search, All / Apps / My processes / System, sortable columns, stable selection and order held under the pointer. Checked on a Mac through the protocol and process samples; still to see by eye, and on Windows. See [Completed work](COMPLETED.md#monitor-processes-phase-4a--2026-10-17).
   - Done, **4b. Overview.** The navigation (icons only below 640 px), the daemon's always-on totals history (`WatchSystemTotals`), CPU, Memory, Disk and Network cards with dot history that open their pages, Memory by type as a ring, 1m / 5m / 15m / 1h ranges and pause, and minimal resource pages (figures and a tall history). Checked on a Mac through tests and process samples; still to see by eye, and on Windows. See [Completed work](COMPLETED.md#monitor-overview-phase-4b--2026-10-17).
   - **4c. Apps.** Processes grouped by application (bundle on macOS, a name-based guess elsewhere) with real icons; Memory by app on the Overview; grouped rows on the Processes page.
   - **4d. Resource pages and GPU.** CPU total/per-core and user/system; memory, available, swap and pressure; disk and network activity with volumes and interfaces; GPU utilization and memory (IOKit on macOS, performance counters on Windows, unavailable elsewhere) as a card and a page.
   - **4e. Inspector and quitting.** Right-hand inspector (identity, CPU/memory history, command/path, start time, state, parent/children), or a detail view with Back in narrow panes. Quit / Force quit as peer actions with confirmation, aimed at `(pid, start time)`; the daemon revalidates both before signalling and never signals a group. Open terminal for Compi-owned processes.
   - **4f. Targets.** Target selector for the Windows host, each WSL distribution (the streaming collector, with PID revalidation and kill inside it) and connected hosts.
   - Later: resizable columns with saved visibility and order.
