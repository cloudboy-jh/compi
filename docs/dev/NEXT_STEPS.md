Features 1 to 3 of the features doc (editor, diffs and Git; program status; settings and cleanup) are done, and Monitor (feature 4) phases 4a–4c shipped in 0.2.0 (published 2026-10-18). Product scope lives in the separate features doc; finished work is in [Completed work](COMPLETED.md).

Done: phase 0, GPUI upgrade (`2e2b9fe`); phase 1, content panes (`4b458be`); phase 2, files and editor (see [Completed work](COMPLETED.md#files-and-editor-phase-2--2026-10-11)); phase 3, file safety (see [Completed work](COMPLETED.md#file-safety-phase-3--2026-10-12)); phase 4, diff view (see [Completed work](COMPLETED.md#diff-view-phase-4--2026-10-12)); phase 5, editor and diff (see [Completed work](COMPLETED.md#editor-and-diff-phase-5--2026-10-12)); phase 6a, stage, commit, discard (see [Completed work](COMPLETED.md#stage-commit-discard-phase-6a--2026-10-12)); phase 6b, editor controls, one tab per file, remote and branches (see [Completed work](COMPLETED.md#editor-controls-tabs-remote-and-branches-phase-6b--2026-10-12)).

**Goal reached:** edit, save, run, review, commit and push Compi itself inside Compi, without opening Zed.

## Left open

- macOS qualification on screen of the editor, file safety, the diff and Git work, the settings and cleanup phases (3a–3f) and the three earlier macOS fixes. Also open: Windows-host and SSH file environments; IME in the editor; live TUI redraws through ConPTY with synchronized output.

3. **Monitor** (feature 4, "Task manager" in the features doc): a resource monitor in a content pane, Pulse's structure (navigation, Overview cards, detail pages, Processes) in Compi's look.    - Shape: a third `PaneContent` kind, `Monitor` (protocol 28, workspace file format 5; a Monitor leaf is stored as a marked Settings leaf so format-3 and format-4 daemons can read the file far enough to refuse it). 4. **Scrolling in TUIs and omp.** Scrolling up while a program prints keeps snapping back to the bottom.
   - Causes, measured on a Mac in `cargo dev`: scrollback is capped by 1 MiB of cell memory (`MAX_SCROLLBACK_BYTES`, about 33 bytes a cell), not the 10,000-line setting, so an 80-column pane keeps 420 of 3,000 printed lines and wider panes fewer. Once full, every new line evicts the oldest, the client sees a history that no longer starts with its old one and resets to the bottom (`gui/workspace.rs` `history_invalidated`). omp and Pi clear and reprint the scrollback (`ESC[2J ESC[H ESC[3J`) whenever something above the screen changes, which does the same. Each scrollback change resends the whole history (`terminal/mod.rs`, `Delta.scrollback`). In the alternate screen without mouse reporting (`less`, `man`, Git's pager) the wheel does nothing, and every trackpad event moves at least a line or sends a whole wheel click, with fractions never added up.
   - **Step 1, done in source for 0.2.1; no protocol-version change.** Text-and-neighbour anchors keep the reading row through eviction and clear/reprint, ignoring style changes. Split clear/reprint frames retain only the reading viewport for a 250 ms grace period; a real clear then returns to live output. Uncertain selections are cleared. A "↓ N new lines" chip returns to the bottom when clicked; typing does too. Per-pane fractional deltas produce only whole local scroll lines, mouse reports or alternate-screen arrows. DECSET 1007 defaults on in the daemon; an optional, backward-compatible JSON Input marker distinguishes synthesized arrows from real keys without changing the binary screen layout. Physical wheel/trackpad and Windows/WSL qualification are still open.
   - **Step 2, protocol 30.** Scrollback deltas carry appended rows and an evicted count, the full history only on attach or a real clear. Rows are stored compactly (text and style runs, trailing blanks dropped) so `scrollback_lines` means lines within a measured memory budget; the client's mirror follows.
   - Step-1 verification done on macOS: 612 workspace tests passed, all-target Clippy with `-D warnings` passed, and engine/live `cargo dev` smoke confirmed eviction/redraw anchoring and fractional scrolling in real `less`.
   - Left before releasing 0.2.1: visually check the new-lines chip and click/type return to bottom; use a physical trackpad and mouse wheel during omp output and in `less`, `man`, `htop` and `vim`; repeat on Windows/WSL. Screen capture and UI automation were unavailable in the implementation session. Publishing 0.2.1 is separate from committing and pushing the fix.
   - Step-2 acceptance: incremental append/eviction transport and compact storage retain the configured 10,000 lines within a measured memory budget; the existing 1 MiB cap has not changed.
