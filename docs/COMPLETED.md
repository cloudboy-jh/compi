### Shell prompt settings — 2026-10-05

- Protocol 16 adds `Prompt { distribution, request }` → `Prompt { response }` with `Detect`, `Preview`, `Plan`, and `Execute` (`compi_protocol::prompt`). The daemon runs everything in its shell environment through POSIX `sh` (local Unix, the remote account behind SSH, or `wsl.exe --distribution D --exec` on Windows); `wsl2_distributions()` lists WSL2 targets. Release metadata and qualification tooling declare protocol 16.
- Detection probes the login shell, providers on `PATH` plus common install directories (Windows `.exe` copies are reported, not used), the Oh My Posh theme cache, Starship presets, `STARSHIP_CONFIG`/`~/.config/starship.toml`, provider-init and managed lines in Bash/Zsh startup files, `state.json`, and backup manifests. Notes explain missing providers, Windows-only installs, unsupported shells, a Compi/login shell mismatch, and a `.bash_profile` that does not load `.bashrc`.
- Styles are used unchanged: Oh My Posh styles are copied through `oh-my-posh config export --format json` (any input format), Starship presets through `starship preset`. Per-segment toggles were built first and removed after review: themes already decide their segments, and adding or removing one broke powerline styling. `Preview` renders up to 32 styles per request in one `sh` run (primary and right prompt after status 0/120 ms) and reports per-style errors.
- Apply/turn-off/restore plan every change: user files get a line diff; the token hashes the operation and old/new contents (the state's timestamp excluded); execution rechecks it and fails with `RevisionConflict` if anything changed. `Apply { config, outside }` always covers Compi shells and adds or removes the login-shell block; `Disable` removes every managed prompt. Each execution first backs up all managed files plus `~/.bashrc`/`~/.zshrc` to `~/.compi/prompt/backups/<id>` (newest 20 kept) and bumps the reload token. The login-shell block is rewritten in place (links and modes survive); restoring a startup file restores only that block. Re-applying identical settings is a no-op.
- Bridge (`assets/compi-shell.sh`): wrappers load `~/.compi/prompt/compi.<shell>` at top level after the user's rc; login Bash loads lazily at the first prompt. A reload token makes running Compi shells restore a snapshot of the user's own prompt state and source `live.<shell>` at their next prompt, then rerun the new hooks once with the real exit status. The prompt hook now preserves `$?`, stays last, and keeps `PROMPT_COMMAND` array indices. Under ble.sh, loading and reloads happen from its ATTACH/PRECMD hooks, and its `prompt_rps1`/`prompt_ps1_*` options and PRECMD/PREEXEC hooks are part of the snapshot. ble.sh draws the first prompt inside `ble-attach`, before its ATTACH hooks, so an rc ending with `ble-attach` used to show the plain prompt until Compi loaded the style. The startup wrapper now aliases `ble-attach` to `_compi_ble_attach` while the rc runs; it loads the applied prompt, then calls the real `ble-attach`, so ble.sh's first draw is already styled. The alias removes itself on first use and after the rc. If ble.sh attached some other way, startup falls back to loading with `ble-edit/restore-PS1`/`adjust-PS1` and a redraw, which can still briefly show the plain prompt. Measured in tmux with the user's `.bashrc` and catppuccin: before, plain prompt at 1,036 ms, styled at 1,470 ms; after, styled at 1,025 ms and nothing drawn before it (no prompt applied: plain at 862 ms). In `cargo dev`, sampling a new tab every ~100 ms showed only a blank cursor, then catppuccin. A fake-`HOME` tmux run covered nothing applied → live apply → `false` → `cd` → turn off, with no leftover alias; the fallback was checked with `\ble-attach`; `tools/test-compi-shell.py` passed.
- Client: a **Shell prompt** group at the bottom of Settings → Terminal plus the **Prompt settings** palette command. Details/Refresh buttons with progress and errors only (target, shells, providers, startup lines, and warnings live under Details); WSL distribution and provider choices only when there is more than one; a style list in which every row renders its prompt with the terminal's resolved font, fallbacks included (so Nerd Font icons match the terminal), and current palette (fetched in background batches of 32, cached, stale replies ignored). The list is a fixed-height, variable-row GPUI `list` that lays out only visible rows and scrolls on its own. Clicking a style opens a dropdown under its row with **Apply**/**Cancel** while the plan loads in the background (Apply waits for it); only a change to `~/.bashrc`/`~/.zshrc` shows its diff there. **Turn off** and each **History** row's **Restore** open the same dropdown under themselves. One dropdown at a time; Escape closes it; the current style and scope opens none. All controls are keyboard-reachable through the offset-based focus model, the dropdown's buttons right after the control they opened under.

### `cargo dev` source loop — 2026-10-05

- New workspace member `tools/compi-dev` (not a default member, not packaged) behind the `.cargo/config.toml` alias `cargo dev`. It polls `crates/`, `assets/`, the root manifests, and itself, hashes content (unchanged saves are ignored), and coalesces bursts (250 ms quiet, 2 s cap). Client inputs rebuild `compi`; daemon inputs rebuild and stage `compi-daemon` without touching the running one; protocol inputs rebuild both and hold the new client until an explicit `r` restart, which uses the consent-gated `ConditionalStop`. Builds use the shared `target/debug` cache; the runner copies binaries into `target/compi-dev/bin` (macOS: a minimal `Compi Dev.app`) so nothing it runs locks a Cargo output.
- Isolation: instance `compi-dev`, `COMPI_DATA_DIR=target/compi-dev/data`, and a seeded dev `config.toml` with update checks off. `paths::data_dir()` and the update GUI-host registry now honor `COMPI_DATA_DIR` on Windows too (previously Unix only); the probe's daemon log follows `data_dir()`. Unset, every path is unchanged.
- Windows: the dev daemon is created as a child of the desktop shell (`PROC_THREAD_ATTRIBUTE_PARENT_PROCESS`, only the log handle inherited), so it leaves Cargo's kill-on-close job; force-killing `cargo` left the daemon and a running shell intact. The preview closes through `WM_CLOSE` on its visible windows, then a 5 s termination fallback.
- One dev instance per checkout: `AGENTS.md` makes `cargo dev` the only sanctioned source preview. On start and on `--stop`, the runner closes previews registered in the default state directory whose executable lies under this checkout's target directory, then stops every `compi-dev`-foreign `compi-daemon` running from there. It uses the consent-gated stop when the instance endpoint is served by that exact PID, and terminates the process otherwise. `compi_protocol::local_daemon_processes()` exposes the existing per-user daemon inventory for this. Smoke: a hand-launched `target\debug` daemon (`--instance stray-smoke`) was stopped with its shell count reported, and the installed daemon kept its PID.
- Windows/WSL2 native smoke: preview launched and reattached; a client edit swapped the window with the same surface `process_lifetime_id`; a compile error printed diagnostics and kept the old preview PID; a client that compiled but panicked at startup was rolled back to the previous binary and not retried; a daemon edit staged a build and left the daemon PID unchanged; a protocol edit held the client, and `r` stopped the daemon with consent (shell → `lost`) and opened the new client; `q` and a real console Ctrl+C closed the preview and kept the daemon; `cargo dev --stop` ended it. No file under `%LOCALAPPDATA%\Compi` changed, and seven unrelated daemons kept their PIDs.
- Timing (Windows debug): cold start from an empty target directory 78.5 s client + 10.8 s daemon + 1.0 s preview; warm start to visible preview 2.1 s. One-line `workspace.rs` change: build 11.7–12.4 s (`compi-client` lib 7.8 s, of which 4.3 s codegen; `compi` link 3.2–3.8 s), swap 1.1 s, save to visible 13.3–14.0 s; a `bin/compi.rs`-only change built in 3.0 s. ### Layout presets — 2026-10-01

The daemon accepts a tree only when its leaves are exactly the tab's current pane/surface pairs, launches and ends nothing, and stores the replaced tree as the tab's additive, defaulted `previous_layout`. Remove/detach also drop that pane from the stored tree; the workspace format stays version 1. Release metadata and qualification tooling now declare protocol 15.

- GUI: **Arrange panes…** (palette and tab menu; renamed **Arrange panes and tabs…** on 2026-10-02) with wireframe preview, overflow warning, M/F toggles, and Delete-twice preset removal; **Mirror/Flip/Restore previous pane arrangement**, **Save pane arrangement as preset…**, and **Swap pane left/right/up/down**, all unbound by default. ### Floating panes — 2026-10-01

- Implemented window-local floating for existing terminal panes. Floating reuses the pane's single attached view and PTY, with no duplicate surface or second attachment. The pane leaves only this window's tiled layout; siblings reflow and divider mutations are translated back to the saved tree, which the server never changes. Floats stay attached across tab and workspace switches. They move and resize with clamped minimums, resize their PTY, and are remembered per window slot as additive, defaulted client state, which older clients ignore. Dock is presentation only and follows the pane wherever the server tree now places it. Removing its pane, or hiding or moving its tab out of the window, ends the float and releases the attachment.
- Keyboard ownership is explicit. One view owns input, and the owning float is outlined and labelled **Keyboard**. New palette commands: **Float pane**/**Dock pane**, **Switch focus between floating and tiled panes**, and **Focus next floating pane**, all unbound by default. Split, zoom, and divider commands are disabled for a floating pane with a Dock reason. Remove/End keep their confirmations, and modal overlays render above floats.
- Windows/WSL2 native smoke (isolated debug instance, synthetic window messages, not physical-input qualification):
  - A split pane floated with its shell PID unchanged (29023), and its PTY followed the frame from 30×53 to 16×49 and 17×50.
  - The float stayed visible and typeable over a new tab, and the focus command moved typing between float and tile.
  - Dock restored the original right-hand split at 30×53 with the same PID. `compi-probe workspace` showed the server split tree unchanged while floating.
  - A relaunch restored the float's placement and keyboard ownership, float cycling raised the back float, and the floated single-pane tab showed its Dock placeholder.
  - Removing a tab through the existing confirmation dropped its float and returned typing to the tiles.
  - New unit tests cover pruned-tree divider addressing, frame clamping, cross-tab focus/move/hide/removal reconciliation, state sanitizing, and command enablement. All 127 `compi-client` tests, warning-denied workspace Clippy, and rustfmt passed.
- Fixed jerky float move/resize: the occluding frame hid the root drag handler until the pointer left the old frame, so floats jumped instead of tracking. The frame now forwards drag moves itself. With 40 small steps, a (−200, −150) move and a (+150, +80) corner resize now land exactly, where before a (−200, +200) move landed short at (−169, +170). Float frames now use the rounded corners of the other overlays.
- The tab menu's pane bubble now offers Detach · Float · End… (Float reads Dock for a floating pane), and floating panes are marked in the pane list and hover card. Floating a pane from a tab that is not shown attaches its view first. Windows smoke: Float from the bubble moved typing to the float, reopening showed the Floating mark and Dock, and Dock restored the split.
- Split and sidebar seams are now one-device-pixel hairlines in the theme border color, replacing 5px solid bars. Each keeps a transparent 8px drag zone and turns accent on hover and while dragging. Windows smoke: a split seam grabbed 3px off the line moved by the drag distance, and the sidebar seam resized from inside the sidebar edge. Canvas sizing now uses an aligned viewport as-is, removing a phantom full-width workspace scrollbar caused by sub-pixel rounding with the sidebar open; a layout regression test covers the unaligned case.
- Right-clicking a tab no longer selects it, so its menu can float a pane from a tab you are not viewing; tab command rows select the clicked tab before running. Menus and the palette now go stale only when the workspace structure (hierarchy, labels, pane leaves, process lifetimes) changes, not on the revision bumps from resize or status observations that previously produced "Workspace changed while the terminal menu was open" right after a menu opened. Destructive confirmations still bind the exact revision. Seams now blend the border color 40% toward the terminal background. Windows smoke: with tab 2 selected, tab 1's menu stayed valid after a 2.5s wait, Float showed tab 1's agent shell (same PID 33624) over tab 2, and Rename from tab 1's menu renamed tab 1.
- Not exercised: macOS, multi-window attachment conflicts with a floated surface, physical keyboard/IME, and mixed-DPI drags.

## Completed: Phase 3 — durable workspace ownership

### Implemented

- Protocol v8 introduces distinct server, generation, session, tab, pane, surface, process-lifetime, mutation, and attachment identities. Terminal controls and screen frames carry enough identity to reject traffic from stale attachments or restarted processes.
- A single-writer workspace actor serializes mutations and runtime observations through bounded queues. It validates server generation and expected revision, fingerprints mutation content with SHA-256, retains a bounded durable receipt history, persists before publication and acknowledgement, and schedules process effects only after durable intent.
- The versioned `workspace-v1.json` store atomically replaces durable state. Legacy v1/v2 shell records migrate once into an imported session with one tab/pane/surface per record while retaining an exact backup. Interrupted migration reuses an identical backup; malformed current metadata is quarantined with a visible recovery message; active records reopen as `Lost`.
- Stable surfaces now have a fresh process lifetime for every launch attempt and a fresh attachment identity for every controller. Restart preserves the surface ID, rejects old-lifetime attachment and terminal traffic, and resets terminal state through a fresh authoritative snapshot.
- Session/tab/pane removal persists `Ending` intent before process cleanup and removes structure only after cleanup succeeds. Cleanup failure retains the affected structure and error for explicit recovery.
- The daemon, typed client, diagnostic probe, Windows console, and existing GPUI surface integration use the new workspace protocol. Ordinary client launch initializes only a never-initialized workspace; intentionally empty or lost workspaces do not create shells implicitly. Full hierarchy presentation remains Phase 4.

## Phase 4 — workspace client implemented

### Agreed UI direction — 2026-09-07

- **Primary:** Ghostty-like top terminal tabs. Each tab opens one terminal or its complete split layout, not an entire workspace. Creating, switching, reordering, and hiding tabs must work without opening the sidebar.
- **User-facing hierarchy:** Workspace → Terminal tabs → Panes. A named UI workspace maps to the existing server `Session`; the server's `Workspace` root remains the collection of all such groups. Do not introduce a separate session navigation layer or rename the protocol/persistence model for UI terminology.
- **Secondary:** a full Superterminal-style sidebar for browsing expandable workspaces and their tabs, organizing work, and finding/restoring hidden work. It supplements the top tab bar; it never replaces it. Every new or relaunched window starts with the sidebar closed, including tear-off windows. Remember width, not open visibility; expose a quiet chrome toggle, shortcut, and palette command, with no permanent rail, large selector, or reserved width when hidden. Reconnect, workspace switching, and tab creation/transfer never open it automatically.
- **Native windows:** dragging a terminal tab outside its window creates a new window containing that same tab and all its splits. Dropping onto another window transfers the tab there. Preserve workspace membership (server `Session`), surface identities, process lifetimes, contents, and valid focus/viewport state; never clone or respawn work.
- **Safe transfer:** keep the source attached during the drag; Escape cancels without moving anything. Accept a drop through an explicit attachment handoff, never concurrent controllers or PTY resize fights. Failed window creation/attachment keeps or restores the source view with a visible error. Moving the last tab leaves an empty source window, not a replacement shell.
- **Presentation ownership:** existing destination windows keep their own appearance overrides, zoom, and sidebar state. A new tear-off window inherits the source's resolved theme, opacity, background effect, zoom, and sidebar width but starts with its sidebar closed. Global appearance defaults live in TOML; private JSON stores only explicitly changed window fields; CLI theme overrides remain invocation-only.
- **Dark Glass and themes:** Dark Glass remains the default with neutral-dark surfaces, acid-green accent, and restrained native materials. Warm Carbon remains the coordinated alternative. Quick Appearance and Settings expose both presets plus 10–100% terminal opacity and clear/blurred native backgrounds, with readable opaque/reduced-transparency fallbacks.
- These decisions replace the earlier sidebar-first and opaque-terminal-only presentation plans.


### Implemented boundaries

- `gui.rs` and `gui/workspace.rs`: top terminal tabs, optional expandable workspace sidebar, all-pane rendering, native input/overlays, lifecycle actions, split overflow, window transfer, and whole-app appearance.
- `client_state.rs`: exclusively locked remembered slots, atomic state writes, quarantine/recovery, hidden membership, navigation fallback, and sequence/identity/fingerprint-validated viewport anchors.
- `layout.rs` and `commands.rs`: shared measured layout constraints and one typed command registry with platform shortcuts and disabled-action explanations.
- `config.rs` and `theme.rs`: versioned TOML with atomic appearance updates that preserve comments/unrelated keys, launch profiles/environment/limits, override provenance, Dark Glass/Warm Carbon, terminal opacity, and clear/blurred background effects.
- `window_host.rs`: authenticated, bounded same-user local forwarding so ordinary same-instance invocations create windows in one GUI process.
- Protocol v9/server integration: measured split admission, root-relative divider paths, ephemeral environment context with persistable launch profiles, authoritative Clear scrollback, retained read-only exited grids, and retirement of obsolete runtime/controllers.
